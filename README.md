# Two-Stage RAG Chatbot & Evaluation Suite

A Retrieval-Augmented Generation (RAG) system built with **ChromaDB**, **Sentence Transformers**, and **Google Gemini**. The project implements a two-stage retrieval pipeline (dense vector search followed by cross-encoder re-ranking) and a rigorous evaluation harness that tunes chunking strategies and retrieval parameters across an automated synthetic benchmark.

---

## 🚀 Key Features

- **5-Document Corpus**: Multi-domain factual corpus covering Cephalopod biology, Honeybee communication, Mars robotic exploration, Alan Turing's computing foundations, and Deep-sea hydrothermal vents (`1,324` total words in `data/` and `sample_data.txt`).
- **Two-Stage Retrieval Pipeline**:
  - **Stage 1 (The Net)**: Fast semantic vector search using ChromaDB and dense embeddings (`all-MiniLM-L6-v2` / `gemini-embedding-001`) to retrieve top-$k$ candidates ($k \in \{5, 10, 20\}$).
  - **Stage 2 (The Scalpel)**: Cross-encoder re-ranking (`cross-encoder/ms-marco-MiniLM-L-6-v2`) scoring query-document pairs to prioritize the most relevant context chunk ($k \in \{1, 3\}$).
- **Gemini Flash-Lite Generation**: Generation powered by `gemini-3.5-flash-lite`, selected dynamically via `client.models.list()`.
- **Resilience & Caching**: Exponential backoff on HTTP 429 rate limits, with persistent disk caches for prompt completions and embedding vectors.
- **Evaluation Harness & Tuning Grid**: Comprehensive grid search across **42 configurations** exploring chunk sizes (30, 50, 80 words), sliding-window overlaps (10%–20%), and two-stage top-$k$ combinations.

## 📊 Benchmark & Evaluation Results

> [!NOTE]
> **Evaluation Scope & Limitations**: This benchmark is **small and synthetic** (50 Q&A pairs generated from a 5-document, 1,324-word corpus). While it demonstrates the relative behavior of chunking, vector retrieval, cross-encoder re-ranking, and grounded generation, results on large-scale, out-of-domain production corpora may differ.

### Dataset & Split
- **Golden Dataset**: 50 synthetic question-answer pairs (`golden_dataset.json`) generated by `generate_benchmark.py` with verbatim source evidence sentences from each document.
- **Split Protocol**: Deterministic 50/50 partition using `seed=42`:
  - **Dev Split**: 25 questions (used exclusively for grid-tuning chunk sizes, overlaps, and top-$k$).
  - **Test Split**: 25 held-out questions (used exclusively for final reporting).

### 42-Configuration Grid Search (Tuned on Dev)
Explored on the Dev split:
- **Chunk sizes**: 30, 50, 80 words
- **Overlaps**: 10% to 20% (plus 16.7% baseline)
- **Stage 1 top-$k$**: 5, 10, 20
- **Stage 2 top-$k$**: 1, 3
- **Best configuration identified on Dev**: Chunk Size `30`, Overlap `3` (10.0%), Stage 1 top-$k=5$, Stage 2 top-$k=1$ (yielding 100.0% Hit@1 and 1.000 MRR on Dev).

## 🛠️ Setup & Installation

### 1. Prerequisites
- Python 3.10+ (tested on Python 3.13)
- Google Gemini API key ([Get one here](https://aistudio.google.com/))

### 2. Virtual Environment & Dependencies
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 3. Environment Configuration
Copy `.env.example` to `.env` and set your API key:
```bash
cp .env.example .env
```
Edit `.env`:
```ini
GEMINI_API_KEY="your_actual_gemini_api_key"
```

---

## 📖 Usage Guide

### 1. Ingest Documents into Vector Database
Process and store the corpus (`sample_data.txt`) into persistent ChromaDB storage:
```bash
python ingest.py
```

### 2. Run the Interactive Two-Stage RAG Chatbot
Ask questions grounded strictly in the ingested corpus:
```bash
python main.py
```

### 3. Generate Benchmark Dataset
Synthesize 10 factual Q&A pairs per document using `gemini-3.5-flash-lite`:
```bash
python generate_benchmark.py
```

### 4. Run Quantitative Evaluation
Run the full 42-configuration grid search on the dev split and evaluate baseline vs. best configuration on the held-out test split:
```bash
python evaluate.py
```
